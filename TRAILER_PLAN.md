# How To Train Your AI - Trailer Plan

## Trailer Direction

Create an `80-85 second` YouTube horizontal trailer for `How To Train Your AI`.

Core identity:

- Format: `16:9 YouTube horizontal`
- Goal: project showcase, not sales trailer
- Audience: social media/general audience
- Tone: friendly sci-fi, upbeat playful
- Narrator: the robot companion
- Language: English
- Visual style: minimal cinematic gameplay with light holographic UI overlays
- Learning message: `AI improves through feedback and measured performance`
- Scope: all minigames
- Ending: portfolio ending with your name/team/project context

## Main Concept

The trailer should feel like the robot is speaking to the viewer:

> I was built to learn. But I need you to train me.

The viewer should understand:

- The player trains a robot/AI through challenges.
- Each challenge measures performance.
- Feedback improves the robot's abilities.
- The game teaches AI training ideas through gameplay, not lectures.

## Trailer Structure

Target: `80-85 seconds`

| Time | Section | Purpose |
|---:|---|---|
| `0-5s` | Hook | Fast gameplay flash + robot line |
| `5-15s` | Game idea | Explain the player trains an AI robot |
| `15-30s` | Minigame 1 | Movement/control training |
| `30-45s` | Minigame 2 | Path/energy decision training |
| `45-60s` | Minigame 3 | Puzzle/problem-solving training |
| `60-72s` | Feedback loop | Scores, stats, improvement |
| `72-85s` | Portfolio ending | Title, project identity, creator/team/tools |

## Recommended Voiceover Script

Use an AI voice, but make it sound like the in-game robot companion.

```text
[0-5s]
I was built to learn.
But I need you to train me.

[5-15s]
In How To Train Your AI, you guide a robot through challenges designed to teach it how to move, decide, and improve.

[15-30s]
First, I learn control.
My stability, path accuracy, camera alignment, and speed are tested as you help me complete the course.

[30-45s]
Then, I learn how to make better decisions.
Every move matters, because the shortest path is not always the smartest one when energy is limited.

[45-60s]
In the lab, training becomes problem solving.
You guide me through grid-based tasks, obstacles, and puzzles that test planning and precision.

[60-72s]
After every challenge, my performance is measured.
Scores become feedback.
Feedback becomes improvement.

[72-85s]
How To Train Your AI.
An educational Unity game project about learning, feedback, and smarter AI behavior.
Created by [Your Name / Team Name].
```

## On-Screen Caption Style

Keep captions short. Do not write full paragraphs on screen.

Use text like:

- `TRAIN THE AI`
- `MEASURE PERFORMANCE`
- `IMPROVE ROBOT STATS`
- `MOVEMENT TRAINING`
- `PATH + ENERGY DECISIONS`
- `GRID-BASED PROBLEM SOLVING`
- `FEEDBACK -> IMPROVEMENT`

Style:

- White text
- Cyan/blue accent lines
- Thin sci-fi borders
- Dark transparent background panels
- Minimal animations: fade, slide, light scan line
- Avoid cluttering gameplay UI

## Shot List

Capture these types of footage:

1. Fast hook montage
   - Robot moving
   - UI/result screen flash
   - Puzzle/grid moment
   - Door/lab/scene transition if visually strong

2. Intro/world shot
   - Main environment
   - Robot visible
   - Player approaching/interacting if possible

3. Minigame 1 footage
   - Robot moving along track
   - Drift/camera/speed challenge moments
   - Result screen or score UI
   - Any visible stat improvement

4. Minigame 2 footage
   - Grid/path movement
   - Energy or path efficiency UI
   - Player choosing tiles/moves
   - Result screen

5. Minigame 3 footage
   - Lab/grid view
   - Robot navigating
   - Pushable devices/tasks
   - Puzzle completion moment

6. Feedback loop footage
   - Result screens
   - Robot stats
   - Score/tier display
   - Before/after behavior if available

7. Ending footage
   - Clean hero shot of robot
   - Game title
   - Creator/team credit
   - Unity educational project label

## Editing Rules

Use this pacing:

- `0-5s`: fast cuts, 0.5-1s per shot
- `5-60s`: medium cuts, 2-4s per shot
- `60-72s`: slightly faster, show scores/stats/improvement
- `72-85s`: slower, clean ending/title card

Do:

- Keep gameplay as the main focus.
- Use the robot image only as a narrator/identity element.
- Show UI only when it proves the learning system.
- Keep the trailer honest: only show features that look stable.
- Make every line match visible footage.

Avoid:

- Long static shots.
- Too much text.
- Explaining code.
- Overusing the robot image.
- Making it sound like a commercial with "play now" language.
- Showing unfinished/debug visuals unless intentionally framed as dev progress.

## Music + Audio

Use upbeat playful music with light futuristic elements.

Best style:

- Bright synths
- Light beat
- Curious/friendly mood
- No heavy bass drops
- No epic combat trailer feel

Audio balance:

- Voiceover should be clear.
- Music should sit lower under the voice.
- Keep some gameplay SFX if they are clean.
- Reduce harsh UI/click sounds.

## Recommended Production Plan

1. Record all gameplay clips first.
2. Pick the best 3-5 seconds from each minigame.
3. Build a rough edit without voiceover.
4. Add the robot voiceover.
5. Add captions and holographic overlays.
6. Add music and balance audio.
7. Add title/portfolio ending.
8. Export a test version and check if the idea is understandable without explanation.

Best target export:

- Resolution: `1920x1080`
- FPS: `60fps` if gameplay is smooth, otherwise `30fps`
- Format: `MP4 / H.264`
- Length: `80-85 seconds`
